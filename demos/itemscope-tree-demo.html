builtIns.itemscopeTree demo

Builds a launch summary from a JSON API response (data/launch.json, a fictional launch modeled on the SpaceX API v4 shape). Each part of the response is paired with an itemscope manager class, whose static instantiate creates the element and whose ish instance manages it.

What this demo exercises
  • map controls which keys are used and in what order. The response's id, flight_number and upcoming keys aren't in the map, so they're ignored.
  • Class entries are registered automatically. PatchImage and CrewList declare static itemscope, so their names survive bundling.
  • A string entry: MissionTitle is registered up front and referenced by name.
  • A key missing from the response: status is instantiated with undefined, and derives its badge from ctx.from.
  • Every value type: strings (name, date_utc), null-able strings (details), objects, arrays (crew, cores), and an empty array (failures). Non-object values are handled by static onAssigned.
  • Nested trees: RocketCard runs a second itemscopeTree over the rocket object using the <Key>ISM naming convention, which picks up HeightISM, MassISM and EnginesISM and skips unregistered keys.
  • itemprop is always set with map, and the CSS grid places every child by it.
  • Updates through ish, synchronous by default, with an async onAssigned (LinksBar) whose calls are applied strictly in order.
