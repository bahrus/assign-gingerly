builtIns.tree — native arrays (proposal)

Proposal — doesn't work yet. This page shows how arrays could be declared natively in builtIns.tree. Until that's implemented, the build stops with a "not implemented yet" notice; once it is, this page should work unchanged. Compare with the working tree demo, which delegates its lists to builtIns.manageTemplateList.

The same launch summary, from the same response (data/launch.json). The links, crew, cores and failures lists are declared with a repeat object in the children slot — { each, key, empty, of } — so no <template id>, no globalThis:// protocol, no querySelector paths, and no fire-and-forget handler.

The proposed array syntax
  • An object in the children slot means "repeat"; an array there still means static children: ['ul', pattern, { each, key, empty, of }].
  • each is an ordinary element specification, stamped once per item. Inside it, ?. is the item, and $parent is the object that holds the array.
  • key (optional) is a path into each item, used to reuse items' elements across reruns; by default items are keyed by index.
  • empty (optional) is a specification rendered instead when the array is empty (or missing) — replacing the old hidden: '?.length' trick.
  • of (optional, default '?.') is the path to the array, relative to the node's value: of: '?.linkList' repeats over the links manager's getter.
  • The repeat object is the repeat boundary that compiling would later turn into a per-item <template>.
